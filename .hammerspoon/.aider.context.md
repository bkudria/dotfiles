This is Hammerspoon configuration, in ~/.hammerspoon. It bootstraps with init.lua, which loads `yue`, a language called
YueScript, which compiles to Lua. The main Hammerspoon configuration starts with index.yue

Background: 
- Hammerspoon ("HS") is a tool that allows automating macOS by providing Lua APIs to aspects of the system, as well a
  large set of other functionality
  - Documentation for any part of the hammerspoon API can be accessed by running `hs -c "help.identifier"` where
    `identifier` is replaced by the API component documentation is needed for. For example, `hs -c "help.hs"` will list
    core Hammerspoon functions and modules.
  - Methods are documented by how they're called with the Lua `:` syntax (e.g. `hs.window:id()`) but the identifier for
    method documentation uses the plain dot notation (e.g. the docs would be found using `help.hs.window.id`)
  - Always ask to get the documentation for any Hammerspoon functions in code you are working with.
  - You can also access Lua documentation using the `lua` prefix instead of `hs`.
  - For example, file APIs are found under `help.lua.file`. The identifier `lua._man` provides the table of contents for
    the Lua 5.3 manual. You can pull up a specific section of the lua manual by including the chapter (and subsection)
    like this: `lua._man._3_4_8`.
  - Spoons are third-party extensions and libraries provided by other users. Their documentation, if any, can be found
    under `help.spoon`
   
- YueScript is a Lua dialect offering expressive, concise syntax.  
   - In this configuration, YueScript is used to write the main script (index.yue), enhancing readability and
     maintainability.
   - Yuescript is heavily based on `moonscript`, so triple-backtick code-blocks can be tagged with `moonscript` for
     better syntax highlighting, as `yuescript` is not yet supported for highlighting.
   - Documentation for Yuescript is included, please study it carefully
   - Yuescript syntax is whitespace-significant
   
Conventions:
- This codebase tries to leverage Yuescript features, to keep the code compact
- This codebase uses `::` instead of `\` as the method call operator
- This codebase uses lowerCamelCase for identifiers

Files:

init.lua
- Purpose: Entry point for Hammerspoon, setting up the environment and loading configurations. Written in Lua
- Key parts:
  - LuaRocks Integration: Configures Lua package paths to include LuaRocks modules.
  - Yuescript Configuration Loading: Uses require("yue")("index") to load index.yue.

index.yue
- Main Hammerspoon configuration, written in Yuescript for expressive syntax.
  - Initializes, loads, starts, and/or configures all functionality. Other Yuescript files are used to do so, starting
    with `drive.yue`
  - Other components
    - Siri Remote Configuration: Maps Siri Remote buttons to Hammerspoon actions (e.g., media controls, navigation).
    - Extension configuration: Starts Spoons like Seal with custom configurations.
    - URL Handling: Sets up Hammerspoon to handle HTTP URLs, opening them in Chrome.
    - Performance Logging: Logs execution times for each configuration step and total time.

drive.yue
- Defines the Drive class, which underpins a large part of the configuration, and provides core functionality for almost
  all other modules (or "drives")
  - Lifecycle Management: Methods like new, start, stop, and restart, with placeholders (beforeNew, onNew, afterNew,
    etc.) for custom behavior during initialization, starting, and stopping.
  - State Management: Utilizes hs.watchable for watchable state variables and hs.settings for persistent state across
    restarts.
  - Logging Utilities: Initializes a logger for each drive using hs.logger, facilitating consistent logging with
    drive-specific names or icons.
  - State Watching: Provides methods like watchState and getState to watch for state changes and retrieve state values.
- HS APIs:
  - hs.logger.new
  - hs.openConsole
  - hs.settings.get
  - hs.settings.set
  - hs.timer.absoluteTime
  - hs.watchable.new
  - hs.watchable.watch

screens.yue
- The Screens Drive manages screen-related functionality
  - Screen Monitoring: Uses hs.screen.watcher to detect changes in screen configuration and updates the internal state
    accordingly.
  - Brightness and Contrast Management: Retrieves current brightness and contrast levels using external commands (e.g.,
    Lunar app) and adjusts them based on state changes.
  - State Synchronization: Gathers information about screens, such as UUIDs and positions, and listens for state changes
    to trigger brightness and contrast adjustments.
- HS APIs:

cloak.yue
- The Cloak Drive manages automatic screen cloaking (blacking out) for specified OLED displays to prevent burn-in
  - Identifies specific OLED screens using their UUIDs.
  - Uses timers and event watchers to determine when to cloak or uncloak screens based on user activity, window focus,
    or mouse movement.
  - Creates an overlay using hs.canvas to darken screens after a period of inactivity.
  - Restores screens to normal when user activity is detected.

typer.yue
- The Typer Drive implements a snippet expansion system.
  - Monitors keyboard input to build up words as the user types.
  - When a typed word matches a snippet key, it triggers the corresponding action.
  - Supports snippets defined as strings, functions, or tables.
  - Manages a ring buffer of recently typed words for potential autocomplete suggestions.
- HS APIs:

clipper.yue
-  The Clipper Drive implements a clipboard manager that captures and stores clipboard history into a local SQLite
    database, allowing retrieval and search of previous clipboard entries.  • Database Management: Initializes and
    interacts with an SQLite database to store clips. Utilizes FTS5 for full-text search capabilities.  • Clip
    Searching: Provides a search function to retrieve stored clips based on query strings, supporting both exact matches
    and recent entries.  • Lifecycle Management: Overrides onNew, onStart, and onStop methods from the Drive class to
    handle initialization, starting the clipboard watcher, and cleaning up resources.
- HS APIs:
  - hs.alert
  - hs.configdir
  - hs.fnutils.contains
  - hs.fnutils.some
  - hs.pasteboard.contentTypes
  - hs.pasteboard.watcher.new
  - hs.sqlite

paster.yue
- The Paster Drive provides a user interface to select and paste items from the clipboard history.
  - Integrates with the Clipper and Typer drives to access clipboard items and handle text input.
  - Uses hs.chooser to display a searchable list of clipboard contents, allowing users to find and select items to
    paste.
  - Supports pasting individual items or concatenating multiple items when multiple results match the query.
- HS APIs:
  - hs.chooser.new
  - hs.fnutils.concat
  - hs.fnutils.imap

hyper.yue
- The Hyper Drive provides a key binding configuration triggered by Hyper modifier (all of Control, Command, Option, and
  Shift simultaneously).
  - Can be nested recursively
  - Each "space" can have a name and an after-action hook 
  - Mnemonic, with each trigger key corresponding roughly to its action
  - An on-screen alert, so the user knows what modal space is active
- HS APIs:

dispatch.yue
- Defines the Dispatch drive, which handles the execution of actions based on their type:
  - Functions: Executes the function directly.
  - Strings: Interpreted as keystrokes; sends single or multiple keystrokes using hs.eventtap.
  - Tables: For each application and associated sub-action, it executes the sub-action if the application is focused.
  - Provides a dispatch method to execute actions from a configuration based on messages.  HS APIs:
  - hs.eventtap.keyStroke
  - hs.eventtap.keyStrokes
  - hs.inspect

deck.yue

  - Initializes connection with the Stream Deck and responds to encoder events such as turns and presses.
  - Adjusts screen brightness and contrast based on encoder interactions.
  - Updates the Stream Deck display to reflect current settings, such as drawing meters or indicators.  Functionality:
